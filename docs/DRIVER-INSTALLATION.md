# Driver installation (test VM only)

Status: **procedure not executed.** No driver has been built or installed. The
commands below are the intended process for a disposable test VM, not evidence
that they work with the current source.

> **Do not install this driver on a physical machine, a dual-boot
> workstation, or any system that holds data you care about.**
>
> CI produces an **unsigned** development build. Windows 11 x64 will not load it
> in normal mode. Test signing requires disabling Secure Boot and accepting a
> desktop watermark. This is not a production installation.

---

## 1. What the package contains

After `Build-Driver.ps1` and `Invoke-Inf2Cat.ps1`, the package directory
contains:

| File | Meaning |
| --- | --- |
| `STGRExt4.sys` | Kernel driver image (unsigned) |
| `STGRExt4.inf` | Driver package definition |
| `STGRExt4.cat` | Catalog generated by Inf2Cat (unsigned) |
| `README-UNSIGNED.txt` | Warning that the package is not production-signed |

The PDB is in the build output directory, not the package directory, and is
uploaded separately by CI.

The current driver:

- registers as a file system;
- declines every volume with `STATUS_UNRECOGNIZED_VOLUME`;
- creates no volume device object and no drive letter;
- reads and writes no file data.

A successful installation therefore proves only that the package loads and the
FSDO registers. It does not prove that EXT4 works.

---

## 2. Prerequisites

- A disposable Windows 11 x64 virtual machine (Hyper-V, VMware, or similar).
- A checkpoint taken before installation.
- Administrator access in the guest.
- Secure Boot **disabled** in the VM firmware.
- The WDK tooling if you need to test-sign locally (`signtool.exe`).
- The package files copied into the guest.
- A second virtual disk if you intend to test volume recognition later. Never
  attach a physical disk.

The host's real disks must not be passed through to the VM.

---

## 3. Enable test signing

In an elevated prompt in the **guest**:

```powershell
bcdedit /set testsigning on
bcdedit /enum "{current}"
```

Confirm that the output includes `testsigning Yes`. Reboot. The desktop shows a
"Test Mode" watermark. If Secure Boot is enabled, Windows may refuse to enable
test signing; disable Secure Boot in the VM firmware and reboot.

Do not enable `nointegritychecks` or disable Driver Signature Enforcement by
other unsupported means. Test signing is the documented development mode.

---

## 4. Create and trust a test certificate

This is a **test** certificate. It is not a production identity and must never
be used to sign a public release.

In an elevated PowerShell session in the guest:

```powershell
$subject = "CN=STGR EXT4 Test"
$cert = New-SelfSignedCertificate `
    -Type CodeSigningCert `
    -Subject $subject `
    -CertStoreLocation Cert:\LocalMachine\My `
    -KeyExportPolicy Exportable `
    -KeyUsage DigitalSignature `
    -NotAfter (Get-Date).AddDays(30)

$cert.Thumbprint

Export-PfxCertificate -Cert $cert -FilePath .\stgr-test.pfx `
    -Password (ConvertTo-SecureString -String "test-only" -Force -AsPlainText)

Export-Certificate -Cert $cert -FilePath .\stgr-test.cer

Import-Certificate -FilePath .\stgr-test.cer `
    -CertStoreLocation Cert:\LocalMachine\Root

Import-Certificate -FilePath .\stgr-test.cer `
    -CertStoreLocation Cert:\LocalMachine\TrustedPublisher
```

The private key exists only in the VM. Never copy `stgr-test.pfx` to a host, a
repository, or a CI artifact. Delete it when the VM is destroyed.

---

## 5. Sign the package for test loading

The CI artifact is unsigned. To load it with test signing, sign it in the VM:

1. Sign the driver image.
2. Regenerate the catalog, because signing changes the image hash.
3. Sign the catalog.

```powershell
# Locate signtool from the installed WDK/Windows SDK.
$signtool = Get-ChildItem "${env:ProgramFiles(x86)}\Windows Kits\10\bin" `
    -Recurse -Filter signtool.exe |
    Where-Object { $_.FullName -like "*\x64\signtool.exe" } |
    Sort-Object FullName -Descending |
    Select-Object -First 1 -ExpandProperty FullName

& $signtool sign /fd SHA256 /f .\stgr-test.pfx /p "test-only" `
    /a .\STGRExt4.sys

# Regenerate the catalog after signing the .sys.
.\Invoke-Inf2Cat.ps1 -PackageDir .

& $signtool sign /fd SHA256 /f .\stgr-test.pfx /p "test-only" `
    /a .\STGRExt4.cat
```

If `signtool.exe` is not present, the machine does not have the WDK/SDK
signing tools. The unsigned artifact cannot be loaded; do not attempt to bypass
signature enforcement.

Verify:

```powershell
& $signtool verify /v /kp .\STGRExt4.sys
& $signtool verify /v /pa /c .\STGRExt4.cat
```

`/kp` applies kernel-mode policy. A failure here means the driver will not load
under test signing either. Do not proceed by disabling checks.

## 6. Install the service

Preferred method, using the INF:

```powershell
pnputil /add-driver .\STGRExt4.inf /install
```

If `pnputil` does not create the service (a non-PnP file system driver may not
be installed by the PnP path on every build), create it manually:

```powershell
Copy-Item .\STGRExt4.sys "$env:SystemRoot\System32\drivers\STGRExt4.sys" -Force

sc.exe create STGRExt4 `
    type= kernel `
    start= system `
    error= normal `
    binPath= "$env:SystemRoot\System32\drivers\STGRExt4.sys" `
    group= "File System" `
    DisplayName= "STGR EXT4 filesystem driver"

sc.exe start STGRExt4
```

The space after each `=` in `sc.exe` arguments is required by `sc.exe`.

The INF sets `ServiceType = 2` (file system driver), `StartType = 1` (system
start), and `LoadOrderGroup = "File System"`. A manual `sc create` must match
those values, or the driver will not behave like the packaged service.

## 7. Verify load and refusal

```powershell
sc.exe query STGRExt4
Get-Service STGRExt4
driverquery.exe /v | Select-String STGRExt4
```

Expected: the service is `RUNNING`. No volume is mounted and no drive letter
appears. The driver's only implemented behaviour is to register and decline
mount probes.

Check the System event log for load errors:

```powershell
Get-WinEvent -LogName System -MaxEvents 100 |
    Where-Object { $_.Message -match "STGRExt4|STGR EXT4" }
```

In a checked/debug build, debug output goes to `DbgPrint`. Use a kernel
debugger or Sysinternals DebugView with kernel capture enabled. Do not treat the
absence of a message as proof of correctness.

### What success does not mean

A running service means the image loaded. It does **not** mean:

- an EXT4 volume was recognized;
- a mount succeeded;
- a file was read;
- a write was safe;
- the driver is production-ready.

The current mount handler returns `STATUS_UNRECOGNIZED_VOLUME` with
`Information = 0` for every volume. That is the intended Milestone 1 behaviour.

## 8. Uninstall

```powershell
sc.exe stop STGRExt4
sc.exe delete STGRExt4
Remove-Item "$env:SystemRoot\System32\drivers\STGRExt4.sys" -Force
```

If installed through `pnputil`, enumerate and remove the package:

```powershell
pnputil /enum-drivers
pnputil /delete-driver oemXX.inf /uninstall /force
```

Replace `oemXX.inf` with the actual published name. Review the output before
using `/force`; it should remove only the STGR EXT4 package.

Remove the test certificate:

```powershell
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
    Where-Object { $_.Subject -eq "CN=STGR EXT4 Test" } |
    Remove-Item

Get-ChildItem Cert:\LocalMachine\My |
    Where-Object { $_.Subject -eq "CN=STGR EXT4 Test" } |
    Remove-Item
```

Disable test signing and reboot:

```powershell
bcdedit /set testsigning off
```

Restore the VM checkpoint. The cleanest uninstall is to discard the VM.

## 9. Troubleshooting the install

| Symptom | Likely cause | Action |
| --- | --- | --- |
| `sc start` returns error 577 | Signature policy rejected the image | Check test signing, certificate trust, and `signtool verify` |
| Error 1275 / driver blocked | Secure Boot or signature enforcement | Disable Secure Boot in the VM, use test signing, do not bypass checks |
| Service starts then stops | DriverEntry failed | Check event log and debug output |
| `pnputil` ignores the INF | Non-PnP package path | Use the `sc create` fallback, or inspect `setupapi.dev.log` |
| No `\FileSystem\STGRExt4` | Registration failed or driver not loaded | Check service state and debug output |
| A volume is mounted | This build does not mount anything | Stop: you are running the wrong binary or another driver |
| Bugcheck on unload | Lifetime bug | Capture the dump, enable Driver Verifier, report it |

Do not "fix" a signature failure by disabling Secure Boot permanently on a
production machine. Use a disposable VM.
